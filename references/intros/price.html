一、AFP 點計（要知道量級，唔好死背）

AFP 消耗 ≈ 基礎係數(模型等級) × 分段係數(輸入長度) × (token 量 / 一萬)

參考量級（2026，非官方精確公式——以控制台「用量明細」為準）：

動作 消耗（參考）
極速文字生成（mini 類） ≈ 0.5 AFP / 萬 tokens
一般模型 1×~3× 基礎係數
圖片生成（Seedream） ≈ 100 AFP / 張
視頻生成（Seedance 2.0） ≈ 2,000 AFP / 段（重）
OCR（讀圖 token 多） 遠貴過讀純文字

⚠️ 視覺好費：一張圖嘅 token 遠超 1000 字。報價第一件事：問 client 有冇多模態輸入。

三、模型計費（主力消費）

  • 買 Plan 唔等於所有模型 1× 計——按「模型等級 × 上下文分段」折算 AFP。
  • 訂閱外（Plan 冇 / 超配額）按量計：參考 doubao-seed-evolving ≈ ¥6/百萬輸入、¥30/百萬輸出（2026 方舟價）。
  • 組合拳：高頻用小 model（mini，0.5×）、難題先 fallback pro → 慳一半以上（見性能 Playbook §2）。

四、工具 / Harness / Sandbox / 記憶 / 儲存

  • 內置 Harness（搜索等）：Medium 起每月送一部分免費額度（約 500 次/月），超出扣 AFP。
  • Sandbox 代碼執行：計「CU·hr」，落第二條線（雲），唔混入 AFP 計。
  • 記憶 / KB 儲存：儲存按 GB/小時，向量化用 doubao-embedding-vision 計 AFP（見記憶 Tab）。
  • Memory/多 Agent 交談：框架本身免費，但每一步 loop / summary / retry / compaction 都係額外 model call → 「框架免費，但框架幫你行嘅每一步都可能化為 AFP。」

五、報價 6 步流程（直接照做）

  1. 搞清楚 client 場景（純文字 / RAG / 多模態 / video？）。
  2. 對返模型矩陣（有冇 video → 鎖唔鎖 Large？）。
  3. 計 AFP：每動作 AFP（上表）× 日常量；用控制台「用量明細」實測校正。
  4. 拆雲資源：runtime 小時、sandbox、儲存向量、流量——獨立計第二/三線。
  5. 加 eval / shadow eval buffer（Shadow eval 10% 流量 = +10% 模型消耗）。
  6. 報「兩個數」：正常預期（e.g. Medium ¥200/月）+ 爆量方案（e.g. Large ¥500/月），同 client 講「超額知會」。
