📘 呢頁詳細解說（先睇呢度，再落下面文件）

CLI 係成個 AgentKit 生命週期嘅「控制台」：init（起）、config（配）、build（打包）、deploy（部署）、runtime（管）、invoke（call）、knowledge/memory（數據）、mcp（開放接口）、eval（驗證）、sandbox（執行）。你寫嘅 code 唔會自己飛上雲——全部經 ak 踩出去。

最快上手：一個 demo agent（10 分鐘）

# 1) 起項目（模板模式）
agentkit init demo-agent --template agent

# 2) 配環境變數 + 登入
agentkit login --scopes full           # 或用 AK/SK 登入
agentkit config set MODEL_AGENT_NAME doubao-seed-2-0-mini

# 3) 寫好 agent 邏輯（agents 目錄，見「開發 API」Tab）

# 4) 一鍵 config → build → apply
agentkit deploy demo-agent

# 5) call 佢
agentkit invoke demo-agent -m "Hello，自我介紹一下"
agentkit runtime logs demo-agent --limit 50

成個流程圖（記憶用）

init → config → (code) → build → deploy/launch → runtime → invoke
                          ▲                             │
                          └───── eval / logs ◄──────────┘
  • build 只係打包 Docker 鏡像（可以 --local 本地檢視）。
  • deploy = config + build + apply 三合一；launch = build + deploy 兩合一。
  • 部署完嘅嘢叫 runtime（有版本、有 CPU/記憶體、有 concurrency、有日誌）。

環境變數兩層級（最易錯嘅位）

Agent（應用級）  ← MODEL_AGENT_NAME / API 憑證… 所有模式共享
Workflow（工作流級）← 只喺當前 mode 內生效
  • agentkit config set K V 設「應用級」；有 Workflow 拆擋時要分開確認係咪想放邊層。
  • 想喺 runtime 度動態改環境變數（唔重新部署）： agentkit runtime update my-agent --envs-json '[{"Key":"K","Value":"V"}]' --auto-release

揀 mode / 模板先唸清楚

你嘅情況 揀
初學 / 標準 Agent ak init 預設模板
想將現有 Agent 包裝做 runtime ak init --from-agent（包裝模式）
要不支援 prebuilt 嘅行為 Harness / Custom sandbox（見下方）

部署後日常（唔好淨係 deploy 完就算）

  • 體檢：ak runtime show（資源）、ak runtime logs（日誌）、ak invoke -u user-X -s session-1（指定用戶/會話測）。
  • 更新：ak runtime update（CPU/記憶體/instance/concurrency/model 都唔使 rebuild）。
  • 回滾：ak runtime versions → ak runtime release my-agent --rev N。
  • 拆除：ak runtime delete my-agent --yes 或項目目錄 ak destroy。

數據 & 開放能力

  • 知識庫 ak knowledge create/add/update：綁 --knowledge-id 落 runtime，Agent 即講 product docs。
  • 記憶庫 ak memory create：VIKINGDB_MEMORY / MEM0 等 provider，跨 session 記住用戶（見「記憶 / 知識庫」Tab）。
  • MCP 服務 ak mcp service create：將 agent 變成 MCP server（公網 + API Key / 私網 / JWT）俾外部 tool 調用。
  • Sandbox ak sandbox：安全 shell + 檔案，可 --json 非交互執行，codex/agent 注入憑證即 AI 自動跑命令行任務。

驗收前必做：eval

agentkit dataset create --name qa-set --schema "input,reference_output"
agentkit dataset add qa-set --file ./cases.json
agentkit eval run --dataset qa-set --evaluator 相关性 --target demo-agent --json

冇 eval 就唔好叫「上線」。CLI 層嘅 eval 只係起點；自動回流最好用 Studio（見「性能 Playbook」Tab §10）。

常見錯 & 記住

  • ❌ 未 login 就 deploy → 一律 auth 錯；先 agentkit whoami 確認。
  • ❌ 直接改手動 RPM / 唔經 CLI → 部署資訊同 runtime 唔一致，回滾會漏。
  • ✅ 每改一個 prompt/context 就 ak eval run 一次 —— 「好似快咗」唔等於「冇變差」。
